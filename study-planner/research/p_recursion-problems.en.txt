@@ 1|Factorial: value, calls, edges, and depth|Original contract/count synthesis|fact-four
Under the chapter's zero-base factorial policy, compute the result, total invocations, recursive edges, multiplications, and peak depth for input 4. Explain why these counts differ.
---SOLUTION---
1. Descent visits arguments 4, 3, 2, 1, and 0, giving five invocations and four parent-child edges.
2. The base returns one. Unwinding yields 1, 2, 6, and 24; each of the four nonbase invocations multiplies once.
3. Immediately before the base returns, all five frames are live. Thus peak depth is five, excluding the external caller.
4. The returned value is 24. Counting only nonbase calls would give four, but the question explicitly includes the base and root.
---RULE---
For decrement-to-zero factorial, the value is $n!$, calls and depth are $n+1$, and recursive edges and multiplications are $n$. State whether the root and base are included.

@@ 2|Changing the factorial base|Original boundary-policy comparison
A factorial implementation returns one at `n <= 1` and otherwise calls on `n-1`. Compare its counts with the zero-base implementation for n = 6 and n = 0.
---SOLUTION---
1. For six, the one-base version visits 6 through 1: six calls, five edges, and five multiplications. It still returns 720.
2. The zero-base version visits 6 through 0: seven calls and six multiplications, including the redundant multiplication by one.
3. At zero, both return one in one call. The formula of six calls generalized as $C(n)=n$ therefore applies only for $n\ge1$; zero needs its own case.
4. Equal results do not imply equal traces or exact costs. The base policy changes the stopping depth.
---RULE---
Changing the base from zero to one can remove one invocation and multiplication without changing factorial's value. Never transplant exact counts without checking the guard.

@@ 3|A nonreachable base|Original termination counterexample
Over mathematical integers, `f(n)` returns at n = 0 and otherwise calls `f(n-2)`. Classify termination for n = 8, n = 7, and n = -2.
---SOLUTION---
1. Eight follows 8, 6, 4, 2, 0 and terminates in five calls.
2. Seven follows positive odd values and then negative odd values. Zero is never reached because parity is preserved.
3. Negative two follows -2, -4, -6, and so on. Its magnitude increases and no base is reached.
4. Decreasing an integer is insufficient unless the domain is bounded below and child states preserve it. In actual fixed-width signed C, the infinite mathematical trace eventually encounters overflow; it is not a valid infinite C execution model.
---RULE---
A base case must be reachable from every admitted input. Parity and domain preservation matter when decrement steps skip values.

@@ 4|Fixed-step call count|Original formula derivation
Let `f(n)` return when n <= 0 and otherwise call `f(n-3)`. Derive total calls for positive integer n and evaluate n = 14.
---SOLUTION---
1. After $t$ recursive edges, the argument is $n-3t$.
2. The first terminal argument occurs when $t\ge n/3$, so the smallest such integer is $t=\lceil n/3\rceil$.
3. Each edge adds one invocation to the original root. Therefore $C(n)=\lceil n/3\rceil+1$.
4. Fourteen visits 14, 11, 8, 5, 2, -1: six calls. The five positive invocations are distinct from the final base invocation.
---RULE---
For a positive step k and a nonpositive stopping guard, positive input n needs $\lceil n/k\rceil$ recursive edges and one more invocation.

@@ 5|An index increases while the measure decreases|Original interval proof
A function processes `a[i]` then calls on `i+1`, stopping at i = N. Prove termination and exact coverage for an initial i satisfying 0 <= i <= N.
---SOLUTION---
1. Use remaining length $N-i$ as the nonnegative ranking function, rather than the increasing index.
2. Every nonbase edge replaces it by $N-i-1$, which is smaller and nonnegative.
3. Induction proves that the function processes exactly indices $i,i+1,\ldots,N-1$ once, because the parent adds its current position to the child's suffix.
4. There are $N-i$ processing actions and $N-i+1$ invocations. The terminal index N is checked but never dereferenced.
---RULE---
Termination can be proved by remaining work even when a parameter increases. A one-past endpoint is a stopping state, not an array element.

@@ 6|Lexicographic progress|Original well-founded proof
A state (a,b) with nonnegative a and 0 <= b <= M decrements b when b > 0; when b = 0 and a > 0, it changes to (a-1,M). Derive the number of transitions to (0,0).
---SOLUTION---
1. The sum a+b is not a valid decreasing measure when b resets to a large M.
2. The rank $R(a,b)=a(M+1)+b$ decreases by one on both transition types: resetting gives $(a-1)(M+1)+M=a(M+1)-1$.
3. Consequently the exact transition count is $a(M+1)+b$, and invocations including the terminal state number one more.
4. This scalar encoding also proves lexicographic termination. Its arithmetic is mathematical; an implementation must guard rank overflow if it computes the rank explicitly.
---RULE---
A reset of one coordinate does not invalidate termination when a higher-priority coordinate decreases. Encode or prove the lexicographic order explicitly.

@@ 7|Partial correctness without termination|Original logical distinction
Does proving that every returned value of a recursive factorial procedure equals n! establish total correctness? Give a precise missing obligation.
---SOLUTION---
1. A procedure that immediately calls itself on the same input never returns. The implication that any returned value is correct can hold vacuously.
2. To establish total correctness, show a well-founded measure decreases on every executed recursive edge and that base cases cover the minimal reachable states.
3. Also show child arguments preserve the input contract and the combination establishes the parent's postcondition.
4. The factorial recurrence explains the desired value, but a malformed call `f(n)` rather than `f(n-1)` fails the termination obligation.
---RULE---
Correctness of a returned result and existence of a return are different proof obligations. Total correctness requires both.

@@ 8|A sum proof with an empty interval|Original contract proof
Prove that `sum(a,l,r)` with base l = r returning zero and step `a[l] + sum(a,l+1,r)` sums exactly [l,r). State the arithmetic precondition.
---SOLUTION---
1. The empty interval has no terms and therefore sum zero.
2. For nonempty length, the induction hypothesis supplies the sum of indices $l+1$ through $r-1$. Adding the excluded first term gives $\sum_{j=l}^{r-1}a_j$.
3. The measure r-l decreases by one and the accessed index satisfies l < r <= N.
4. Under C signed arithmetic, every computed partial sum and addition must be representable. A representable final sum alone does not guarantee all intermediate operations are safe if cancellation occurs later.
---RULE---
An interval sum proof needs bounds, an empty-case identity, a decreasing length, and representable intermediate arithmetic.

@@ 9|Returned value versus emitted output|Original semantic contrast|around-three
`g(n)` returns zero at n = 0; otherwise it prints n, recursively obtains x = g(n-1), prints n again, and returns x+1. Find both the return value and output for n = 3.
---SOLUTION---
1. The first prints on descent are 3, 2, 1. The base prints nothing and returns zero.
2. Unwinding prints 1, 2, 3. Return values increase to one, two, then three.
3. The output is `3 2 1 1 2 3`, while the returned scalar is 3. There are six printed tokens but four invocations.
4. Counting output tokens as calls, or treating the final printed 3 as the returned value's definition, confuses separate observable effects.
---RULE---
Track printed output and returned values separately. Their ordering and counts depend on different instructions.

@@ 10|One saved local per frame|Original automatic-object trace
Every nonbase call initializes local x = n, calls on n-1, then prints x. For initial n = 4, is the output four zeros or 1 2 3 4?
---SOLUTION---
1. The four nonbase invocations have distinct automatic local objects containing 4, 3, 2, and 1.
2. The child does not reassign the parent's local x merely by using a same-named variable.
3. Returning from the base resumes the smallest nonbase invocation first, producing `1 2 3 4`.
4. Shared pointers or static storage could change this analysis, but neither is stated here. Lexical names do not imply one shared runtime object.
---RULE---
Same-named automatic locals in different recursive invocations are distinct objects. Shared storage must be identified separately.

@@ 11|Post-decrement destroys progress|Original C17 argument semantics
For positive n, `bad(n)` executes `return bad(n--);` after testing n == 0. Does the child's argument decrease?
---SOLUTION---
1. The value of postfix decrement is the old n, so the child receives exactly the parent's entry value.
2. The parent's local n is decremented before the child body starts, but that change is not the child parameter's initial value.
3. Every child repeats the same mistake. No zero base is reached from a positive start.
4. This is a progress defect, not an unsequenced-update example. Writing `bad(n-1)` passes the intended smaller value without changing the parent.
---RULE---
A postfix decrement as the only call argument passes the old value. Separate the child's argument from the parent's later local state.

@@ 12|Pre-decrement changes the continuation|Original C17 output comparison
Compare `f(n-1); print(n);` with `f(--n); print(n);`, using a zero base and initial n = 3.
---SOLUTION---
1. The first form leaves each parent's parameter intact. Unwinding prints 1, 2, 3.
2. The second form decrements each nonbase parent's own parameter before the child. Those saved parameters become 2, 1, and 0.
3. Unwinding therefore prints 0, 1, 2. Both chains reach the base and have four invocations.
4. Equivalent child argument values do not imply equivalent subsequent parent actions. The local mutation changes the continuation.
---RULE---
Pre-decrement and subtraction can pass the same child value while leaving different parent state for the return phase.

@@ 13|Unsigned underflow at the boundary|Original C17 guard diagnosis
An unsigned function stops at n == 0 and otherwise calls on n-2. Explain its behavior for n = 1 and give a safe domain guard for processing pairs.
---SOLUTION---
1. At one the guard is false, and unsigned subtraction wraps modulo one more than the type's maximum value.
2. The child argument becomes a very large odd value, so a proof using decreasing natural numbers no longer applies.
3. For a pair-processing contract, return when n <= 1 before subtracting two. Then every recursive edge starts with at least two and remains nonnegative without wraparound.
4. A signed `n <= 0` guard is not a substitute on an unsigned argument; it is equivalent to checking zero and still misses one.
---RULE---
Guard small unsigned arguments before subtracting a stride. Mathematical negativity is not how unsigned C represents the boundary.

@@ 14|Operand order and pure results|Original sequencing distinction
For pure Fibonacci functions, does `fib(n-1)+fib(n-2)` guarantee left-first execution in C17? Does its mathematical sum depend on that choice?
---SOLUTION---
1. C17 leaves the order of the operand calls unspecified. An animation showing left-first execution must declare that policy or use separate statements.
2. With pure calls, valid arithmetic, and the same input, both orders return the same two values and hence the same sum.
3. If calls print or mutate shared state, the visible trace or later results may depend on order.
4. Executions of the called bodies are indeterminately sequenced; this is different from conflicting unsequenced increments such as `i++ + i++`, which are undefined.
---RULE---
Unspecified call order can coexist with a fixed pure result. Do not invent an output order or confuse it with undefined behavior.

@@ 15|Short-circuit avoids a child|Original logical-operator trace
A palindrome function returns `a[l] == a[r-1] && pal(a,l+1,r-1)` after the length guard. For the byte sequence `abca`, how many recursive invocations occur?
---SOLUTION---
1. The outer endpoints are both a, so the right operand is evaluated and the middle interval `bc` is requested.
2. Its endpoints differ, so `&&` short-circuits. No empty interval is requested.
3. There are two invocations and two byte-pair comparisons; the answer is false.
4. A complete matching length-four input would make three invocations, including the empty base. Exact counts can depend on data even with a fixed size.
---RULE---
Short-circuit evaluation can stop recursion before the theoretical deepest base. Separate worst-case counts from the actual input trace.

@@ 16|A missing returned result|Original C17 return contract
An integer function returns one at n = 0, otherwise calls itself on n-1 but has no return statement after that call. Can a caller safely use its result for n > 0?
---SOLUTION---
1. The child returning does not automatically return that child's value from the parent.
2. Each nonbase invocation reaches its closing brace without supplying an integer result.
3. Under C's return rule, using such a missing result yields undefined behavior. A test run accidentally showing one does not establish correctness.
4. The intended forwarding version must say `return f(n-1);`, or save the child result and explicitly return the required combination.
---RULE---
A recursive call's return does not implicitly return from its caller. Every value-producing path needs the specified return.

@@ 17|Static state survives calls|Original shared-state calculation
Assume static counter c is initialized to zero once. Each nonbase invocation increments c before calling on n-1, and all invocations return c. What do two successive outer calls with n = 3 return?
---SOLUTION---
1. The first call's three nonbase invocations increment the single counter to three. All return paths observe that same final value.
2. The static counter is not reinitialized for the second outer call; three further increments give six.
3. The results are therefore three and six, not three and three.
4. Mathematical input n alone no longer determines the result; the prior counter state matters. Caching only by n would be invalid for this function.
---RULE---
Static state is shared and persistent. Include relevant state in a contract and do not memoize a history-dependent function as if it were pure.

@@ 18|Pointer aliasing across frames|Original object-lifetime reasoning
Each of n nonbase calls performs `++*p` then recurses with the same pointer p. Starting with a writable integer x = 5 and n = 4, find x and explain why passing by value does not isolate it.
---SOLUTION---
1. Every parameter p is a copied pointer value, but all copies designate the same x.
2. Four nonbase calls each increment that object once, producing nine, assuming all increments are representable.
3. Passing by value isolates reassignment of the pointer parameter; it does not duplicate the pointed-to object.
4. If each frame instead had its own local x and passed its address only to its child, a different chain of designated objects would result.
---RULE---
Pointer parameters are copied by value while their pointees can remain shared. Trace identities of objects, not just parameter names.

For base b >= 2, a digit function recurses on floor(x/b) until x < b. Derive calls for positive x and evaluate x = 255, b = 2.
---SOLUTION---

@@ 21|Euclid's trace and invariant|Original number-theoretic proof|gcd-main
Trace gcd(1071,462), count invocations and remainder operations, and justify the preserved result.
---SOLUTION---
1. The states are (1071,462), (462,147), (147,21), and (21,0).

---SOLUTION---

@@ 30|Duplicated power calls|Original repeated-subproblem recurrence

@@ 31|A full binary call tree|Original edge-count proof

@@ 32|Three-child recursion|Original geometric-tree derivation
A routine at positive level k makes three calls at k-1 and stops at zero. Find leaves, invocations, and depth for k = 4.
---SOLUTION---

@@ 33|Fibonacci's exact call count|Original recurrence solution|fib-five

@@ 42|Arbitrary-precision Fibonacci cost|Original bit-complexity distinction
