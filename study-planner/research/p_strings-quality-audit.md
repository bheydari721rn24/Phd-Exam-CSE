# Strings and terminators: quality audit

Status: local verification passed; publication tracked separately. The chapter remains a draft. No subsequent chapter has begun.

## Content review

The main language is ISO C17. Object capacity, logical string length, implicit and embedded zeros, pointer identity, ownership, lifetime and input-stream status are distinguished. Every algorithm includes its assumptions and a proof or invariant. Exact scalar counts are not presented as mandated library machine-instruction counts. Unicode examples explicitly count UTF-8 bytes rather than claiming universal character widths.

There are 80 independently authored or reconstructed complete solutions, 80 corresponding final examination rules, and one original-PDF-rechecked abstract-string counting bridge. Source-derived patterns are labelled. No deterministic output is assigned to an undefined C-library call. A checked simulator rejection is distinct from an actual C program's undefined behavior.

## Visual design

Thirty subject-specific models expose fixed byte indices, zero cells, unread and written regions through actual operation heads, exact comparisons, and complete checkpoints. These are byte-memory, copy, append, movement, matching, filtering and parsing models, not an unrelated generic animation. Counters exclude preflight length-validation scans and explicitly say so. Array writes in the reversal model count two array writes per swap, while the worked source-code analysis separately counts a temporary assignment too.

Source Sans 3, Newsreader, JetBrains Mono and STIX Two Math retain their distinct roles. Formula rendering is native MathML. Complete-fence and script-base checks, rendered typography, diagram containment, label padding, animation controls, reduced motion, print checkpoints, mobile containment and editable input rejection are recorded in the evidence directory.

## Limits

The course pool is finite; inaccessible PDFs are not represented as read. The authentic item is a clearly labelled bridge revisit rather than a new C-library examination question. Exhaustive finite checks are not a proof of every possible C program, and the chapter does not guarantee personal performance on unseen examinations.
